Sobre

Contar laços é fácil. Mas e quando o algoritmo chama a si mesmo? Não há laço para contar, o custo está escondido nas chamadas. A saída é escrever esse custo como uma equação que fala dela mesma.

Relação de recorrência

Veja o fatorial:

static long fatorial(int n) {
    if (n <= 1) return 1;
    return n * fatorial(n - 1);
}

Como esse código funciona

A função resolve um problema grande usando a resposta de um problema um pouco menor: o fatorial de n é n vezes o fatorial de n - 1. A linha if (n <= 1) return 1; é o ponto de parada. Sem ela, a função chamaria a si mesma para sempre.

Acompanhe fatorial(3):

fatorial(3) precisa de  3 * fatorial(2)
  fatorial(2) precisa de  2 * fatorial(1)
    fatorial(1) devolve 1            <- ponto de parada
  fatorial(2) devolve 2 * 1 = 2
fatorial(3) devolve 3 * 2 = 6

As chamadas vão descendo até o ponto de parada e as respostas voltam subindo. Para n, são n chamadas.

A relação de recorrência

Chamar fatorial(n) custa uma multiplicação mais o custo de chamar fatorial(n - 1). Escrevendo T(n)T(n)T(n) para o custo com entrada de tamanho nnn:

T(n)=T(n−1)+c T(n) = T(n-1) + c T(n)=T(n−1)+c

onde ccc é uma constante (a comparação e a multiplicação). Essa é a relação de recorrência. Ela só diz como T(n)T(n)T(n) se relaciona com TTT de algo menor. Falta resolvê-la.

Primeira técnica: expandir

Substitua T(n−1)T(n-1)T(n−1) pela própria fórmula, várias vezes:

T(n)=T(n−1)+c=T(n−2)+c+c=T(n−3)+3c    ⋮=T(1)+(n−1) c \begin{aligned} T(n) &= T(n-1) + c \\ &= T(n-2) + c + c \\ &= T(n-3) + 3c \\ &\;\;\vdots \\ &= T(1) + (n-1)\,c \end{aligned} T(n)​=T(n−1)+c=T(n−2)+c+c=T(n−3)+3c⋮=T(1)+(n−1)c​

Resultado: T(n)=Θ(n)T(n) = \Theta(n)T(n)=Θ(n). Faz sentido, são nnn chamadas com custo constante cada.

Segunda técnica: árvore de recursão

Para recorrências mais complicadas, o melhor é desenhar a árvore de chamadas, anotar quanto cada nível custa e somar os níveis.

Exemplo: busca binária

A busca binária compara com o elemento do meio e continua só em uma das metades:

T(n)=T(n/2)+c T(n) = T(n/2) + c T(n)=T(n/2)+c

Cada nível da árvore tem uma única chamada, custando ccc. Quantos níveis? O tamanho vai caindo n,n/2,n/4,…,1n, n/2, n/4, \dots, 1n,n/2,n/4,…,1, o que dá log⁡2n\log_2 nlog2​n níveis (lembra do exercício do laço que dobra i? É a mesma conta ao contrário). Custo total: c⋅log⁡2nc \cdot \log_2 nc⋅log2​n, ou seja, Θ(log⁡n)\Theta(\log n)Θ(logn).

Exemplo: merge sort

O merge sort divide o array ao meio, ordena cada metade e junta as duas:

T(n)=2 T(n/2)+n T(n) = 2\,T(n/2) + n T(n)=2T(n/2)+n

Montando a árvore, nível por nível:

NívelChamadasTamanho de cada umaCusto do nível
01nnnnnn
12n/2n/2n/2nnn
24n/4n/4n/4nnn
………nnn
log⁡2n\log_2 nlog2​nnnn1nnn

Todo nível custa nnn: quando o número de chamadas dobra, o tamanho de cada uma cai pela metade e os dois efeitos se cancelam. São log⁡2n\log_2 nlog2​n níveis, então

T(n)=n⋅log⁡2n=Θ(nlog⁡n) T(n) = n \cdot \log_2 n = \Theta(n \log n) T(n)=n⋅log2​n=Θ(nlogn)

Exemplo: um caso ruim

Se uma divisão joga tudo para um lado só, como acontece no pior caso do quick sort:

T(n)=T(n−1)+n T(n) = T(n-1) + n T(n)=T(n−1)+n

Expandindo, T(n)=n+(n−1)+(n−2)+⋯+1=n(n+1)2T(n) = n + (n-1) + (n-2) + \dots + 1 = \frac{n(n+1)}{2}T(n)=n+(n−1)+(n−2)+⋯+1=2n(n+1)​, que é Θ(n2)\Theta(n^2)Θ(n2). A árvore aqui é uma “escada” com nnn níveis, cada um custando um pouco menos que o anterior.

Exemplo: Fibonacci ingênuo 

static int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

Aqui cada chamada dispara duas outras, uma para n - 1 e outra para n - 2. Veja fib(4):

                 fib(4)
               /        \
          fib(3)        fib(2)
          /    \        /    \
     fib(2)  fib(1)  fib(1) fib(0)
     /    \
 fib(1) fib(0)

Repare que fib(2) é calculado duas vezes, fib(1) três. A função refaz o mesmo trabalho várias vezes, e isso só piora quando n cresce.

T(n)=T(n−1)+T(n−2)+cT(n) = T(n-1) + T(n-2) + cT(n)=T(n−1)+T(n−2)+c. Como cada chamada gera duas, a árvore tem altura próxima de nnn. Isso dá algo na casa de 2n2^n2n chamadas, ou seja, exponencial. Por isso fib(50) demora minutos e fib(100) nunca termina.

Um atalho: Teorema Mestre

Muitos algoritmos de divisão e conquista têm a forma

T(n)=a T(n/b)+Θ(nd) T(n) = a\,T(n/b) + \Theta(n^d) T(n)=aT(n/b)+Θ(nd)

(aaa chamadas, cada uma com um pedaço 1/b1/b1/b do problema, mais um trabalho ndn^dnd para dividir e combinar). Compare aaa com bdb^dbd:

Se…Então T(n)T(n)T(n) é…Intuição
a<bda < b^da<bdΘ(nd)\Theta(n^d)Θ(nd)o trabalho de cima, na raiz, domina
a=bda = b^da=bdΘ(ndlog⁡n)\Theta(n^d \log n)Θ(ndlogn)todos os níveis custam igual
a>bda > b^da>bdΘ(nlog⁡ba)\Theta(n^{\log_b a})Θ(nlogb​a)o trabalho das folhas domina

Merge sort: a=2a = 2a=2, b=2b = 2b=2, d=1d = 1d=1. Como 2=212 = 2^12=21, cai no caso do meio: Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn). Busca binária: a=1a = 1a=1, b=2b = 2b=2, d=0d = 0d=0. Como 1=201 = 2^01=20, também é o caso do meio: Θ(log⁡n)\Theta(\log n)Θ(logn). Bate com o que fizemos na mão.

Exercícios

Resolva as recorrências.

  1. T(n)=T(n−1)+1T(n) = T(n-1) + 1T(n)=T(n−1)+1
  2. T(n)=T(n/2)+nT(n) = T(n/2) + nT(n)=T(n/2)+n
  3. T(n)=4 T(n/2)+nT(n) = 4\,T(n/2) + nT(n)=4T(n/2)+n
Gabarito
  1. Θ(n)\Theta(n)Θ(n), igual ao fatorial.
  2. Pelo Teorema Mestre, a=1a = 1a=1, b=2b = 2b=2, d=1d = 1d=1, e 1<211 < 2^11<21, então Θ(n)\Theta(n)Θ(n). Na árvore: n+n/2+n/4+⋯≈2nn + n/2 + n/4 + \dots \approx 2nn+n/2+n/4+⋯≈2n.
  3. a=4a = 4a=4, b=2b = 2b=2, d=1d = 1d=1, e 4>214 > 2^14>21, então Θ(nlog⁡24)=Θ(n2)\Theta(n^{\log_2 4}) = \Theta(n^2)Θ(nlog2​4)=Θ(n2).

Resumo

  • Um algoritmo recursivo é descrito por uma relação de recorrência que expressa T(n)T(n)T(n) em função de TTT de entradas menores.
  • Para resolver: expandir a fórmula ou desenhar a árvore de recursão e somar o custo de cada nível.
  • Busca binária é Θ(log⁡n)\Theta(\log n)Θ(logn), merge sort é Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn), e a recorrência T(n)=T(n−1)+nT(n) = T(n-1) + nT(n)=T(n−1)+n é Θ(n2)\Theta(n^2)Θ(n2).
  • O Teorema Mestre resolve de uma vez as recorrências de divisão e conquista da forma aT(n/b)+ndaT(n/b) + n^daT(n/b)+nd.
